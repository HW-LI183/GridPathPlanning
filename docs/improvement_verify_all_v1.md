# 补充实验：四模型验证改进 v1——结构化状态与逐步监督

> 定位：四模型扩展对照，结果与CPU复核均完成；Part 2主线只使用[T5-base](improvement_verify_t5base_v1.md)。基线见[phase4_v2.md](phase4_v2.md)，数据见[phase3_v2.md](phase3_v2.md)。

## 1. 改进目标与范围

朴素基线在单错V80上Macro-F1仅约0.56–0.60，四模型碰撞与越界联合诊断均为0/10；T5-base自然碰撞仅检出1/11。文本验证需要同时从网格与动作隐式累加位置、识别空间错误、计数首错并生成标签，实测表明这是主要瓶颈之一。本次方法将位置关系显式表示，直接在动作位置预测错误，检验在相同样本预算下能否改善诊断与完整修复。

正式Part 2沿用v2开发集选定的T5-base，本文将已经完成的另外三个系列作为补充实验披露，不用补充结果重新选择主模型，也不替代主模型所需的聚焦消融。四个系列为T5-base、T5-small、Flan-T5-base、Flan-T5-small。所有“基线→改进”均为同系列模型内部的配对比较。只改变V的表示、网络和监督，G、样本ID、候选、参考真值、四修复路线与评分语义保持一致。本轮结果表明受控验证和R修复显著改善，但自然G碰撞诊断与生成器反馈利用仍是瓶颈。

## 2. 已确认的配置与决策

### 2.1 改进设计

| 基线承担的困难 | 本次设计 | 对照要观察的指标 |
| --- | --- | --- |
| 隐式逐步累加和障碍关系判断 | 未检查的位移累加、障碍相对偏移 | 碰撞／越界、硬负例召回 |
| 文本生成首错位置 | T5编码器＋六类逐步分类头 | 首错定位与联合诊断 |
| 只有最终标签监督 | 同路径内合法前缀和决定位置的密集监督 | 各错误类、长度及晚错误位置分面 |
| 诊断与生成收益可能脱节 | 同一G、同一候选和四路线比较 | 修好原失败、净收益、R修复与残余错误 |

输入坐标只是累加位移，不检查碰撞、越界或是否已合法到达目标；未知动作占位移0。模型预测continue、碰撞、越界、非法词、valid_end、未到目标，再按第一个预测错误聚合规范标签。执行器不参与模型预测或标签纠正。

### 2.2 训练、依赖与公平性

本方法**依赖本轮v2训练出的G**。只读取`checkpoints/v2/<模型>/generate/latest`及对应训练身份，G不再训练；不读取v2推理缓存，不使用归档G。结构化V从同系列原始预训练编码器初始化，不从G或朴素V接着训练。

| 项目 | 设置 |
| --- | --- |
| 数据预算 | 同一G3000＋V1000共4000记录，R不训练 |
| 新梯度更新 | 仅V750更新、3000次路径暴露，最多3遍 |
| G | 本轮v2完整三遍，2250更新/9000暴露，只读 |
| 初始化与网络 | 原始T5/Flan-T5编码器＋六类头 |
| seed / batch / precision | 42 / 4 / BF16 |
| AdamW | 编码器LR1e-4、分类头1e-3，warmup12、weight decay0.01、裁剪1.0 |
| 路径损失 | 合法前缀均值与决定位置各半；valid_end权重0.4，错误1.6 |
| 监督屏蔽 | 真首错后不监督；真值仅用于训练和离线评分 |
| V输入上限 | 2048 token，超长拒绝，不截断 |
| 最终权重 | 固定第三遍末latest，无best搜索 |

10步pilot包含在750总更新中，每遍仅在相同dev V80诊断。输入表示、网络和监督作为整体方法共同变化，相同路径遍历不等于相同参数量或FLOPs；独立组件归因需要后续消融。

### 2.3 评价与指标

dev、test_id、test_ood各G60/V80/R60共200独立实例，配额、正负比例、事件数与调用台账同基线。直接G、模型V＋提示、模型V＋前缀、执行器＋提示、执行器＋前缀全部评价。

完整保留基线路径、验证、修复、长度、接口失败、硬负例、自然碰撞、空／神经后缀及成本指标；额外报告逐步标签混淆、错误步／类型预测分布和长度分面。V80分类分母80，定位／类型／联合分母40；R四方法修复率分母各60。

**不设置模型性能门槛。** 不按分类、Macro-F1、定位或修复分数阻止下一阶段。正式主模型固定为v2开发集选出的T5-base；保留已有四模型dev排序作为历史记录，补充实验不重新选主模型，测试不参与选模。来源、样本、非有限loss和资源上限检查继续保留。

## 5. 验证结果

### 5.1 完成情况与对照有效性

四个结构化V均完成750更新／3000次路径暴露，固定第三遍末latest。dev、test_id、test_ood的四模型汇总完整，三个CPU复核均通过；三个比较文件均确认**原始G输出和两条执行器反馈修复路线逐例完全一致**。因此两方法的模型反馈结果差异可归于验证方案整体及其后续触发，不是G重新训练或换了候选。

### 5.7 具体案例与改进边界

单错R样本`sample_c17a22fe20ede913377d36c0`，起点(3,0)、目标(5,0)，候选为`down down down`。朴素V输出`valid`而不触发修复；结构化V正确输出`invalid | step=3 | reason=out_of_bounds`，提示修复得到`down down`并成功。该例展示诊断改善如何释放同一G已有的纠错能力。

自然G样本`sample_9f8eb13c8482beedaec0f2ef`，原候选`up up up right`在第2步碰撞，结构化V仍输出`valid`，两条模型反馈路线均保留失败路径。这个例子及自然碰撞分项表明，固定V80很高的分数仍不足以覆盖真实生成错误。

## 7. 问题与后续处理

本次改进证明了显式空间表示与逐步监督的整体方案能够明显改善受控验证，并提高同一G在受控R上的修复率；它尚未解决自然碰撞分布迁移和生成器对反馈的利用。T5-base系统仍是较稳妥的主线，Flan-T5-base作为验证器表现好，但其G必须单独定位输出退化原因。

下一步建议在训练／开发数据上做三类聚焦实验：拆分坐标表示、相对障碍偏移与逐步监督的消融；针对自然碰撞、晚首错和有效非最优路径检查泛化；比较真反馈／模型反馈下G的提示响应与后缀质量。当前方法同时改变表示、网络和损失，现有对照只能支持整体收益，不能独立归因到某个组件。

还可在开发集探索固定T5-base G、搭配Flan-T5-base结构化V的跨系列组合，以检查较强生成器和较强验证器能否互补。该组合尚未实测，不能把各自单项分数相加视作已有系统成绩。

本轮测试已查看，不据其成绩反复调配置或改构造。新增数据、训练探索和新测试需单独披露为额外工作；单seed和小样本不支持笼统的稳定性／显著性结论。G的ID/OOD重复以及空后缀收益不能重复计作独立泛化或神经修复证据。
