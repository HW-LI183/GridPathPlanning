# 项目目录与产物管理

## 1. 目标与范围

工作目录保存完整实验，发布目录保存经筛选的源码和可审查结果。保持数据、检查点和来源绑定所使用的路径稳定，不为整理目录迁移这些文件。

## 2. 顶层目录

| 路径 | 用途 |
| --- | --- |
| `README.md`、`plan.md` | 项目入口、运行顺序和阶段计划 |
| `docs/` | 阶段一至四、发布与目录说明 |
| `configs/` | 训练配方、模型注册和选模锁 |
| `src/`、`scripts/`、`tests/` | 实现、运行入口与短测试 |
| `data/` | 冻结来源、4000G、开发G100/R100与测试数据 |
| `results/` | 数据审计、资源检查和四模型开发结果 |
| `manifests/` | 版本/哈希、来源兼容记录、GPU账本与验收记录 |
| `models/`、`checkpoints/` | 本地预训练文件、微调权重和恢复状态，不进普通Git |
| `logs/`、`third_party/` | 工作站日志、固定上游代码，不进发布包 |

课程说明与论文原文留在原工作目录供阅读，发布包以README中的来源链接说明。

## 3. 数据管理

四模型共享同一冻结数据与布局隔离。数据来源、文件哈希和审计共同确定实验身份，不删除或移动数据来规避检查。最终测试数据保留，但当前没有最终测试推理结果。

## 4. 结果入口

`results/v1/summary_dev.json`和`metrics_dev.csv`覆盖四模型；每模型`dev/cases/`共200条，四者800条，作为逐例审查依据。`review_dev.json`与`figures/`是CPU复核及图表，`results/flan_preparation.json`是文件/分词检查，不是模型性能结果。

## 5. 权重与运行状态

每模型独立使用`checkpoints/v1/<模型键>/`。`best`供推理，`latest`与`_states/`供恢复；训练进度、逐遍评价和完成标记保留。GPU账本累计真实历史成本，不因清理文件归零。现有两份主选择文件均保留，当前正式主选择使用四模型锁`configs/primary_model_v1_four.json`。

## 6. 可以清理的内容

`__pycache__/`和`.pytest_cache/`属于可再生软件缓存，可在进程停止后删除。模型推理`dev/cache/`保留在工作站以便复用，但不进入GitHub发布包；已保存的`dev/cases/`足以审查逐例输出与轨迹。原始日志、权重、优化器状态与冻结清单不随本次整理删除。

## 7. 发布与同步

`scripts/package_repository.py`按白名单生成项目之外的新快照，并输出逐文件大小与SHA-256。快照不含`.git`、权重、运行缓存或日志；已有Git仓库的历史与认证配置保留，通过本地同步更新文件，不新建远程仓库。具体步骤见[GitHub更新说明](github_upload.md)。

## 8. 当前状态

四模型训练和完整开发评价已完成，主模型为T5-base第3遍；800例和24行指标复核通过。阶段五和最终测试尚未开始。工作目录与发布目录相互独立，源码或结果变化后需重新生成发布快照。
